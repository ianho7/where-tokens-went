# where-tokens-went

Use this Skill in Codex when the user asks where their Codex usage went, why usage rose, which Session or project was largest, or what action could reduce repeated context usage.

The invoking Harness is the current Host: use `codex` when running inside Codex. Support for `claude` is paused. If this Skill is invoked from Claude Code, reply: “Claude Code support is paused. No history was read. Please invoke where-tokens-went from Codex.” Do not run the CLI, inspect either Harness's history, or substitute Codex history for a Claude Code request.

## Invocation

Translate the user's requested scope into explicit internal Audit arguments. Resolve the directory containing this `SKILL.md` as `<skill-directory>` and run the bundled `scripts/where-tokens-went.js` with Node only; do not call a global `where-tokens-went` command and do not treat an internal command as the completed request. Use Current Project by default; when the user asks for a Global Audit, widen only the project selector with `--all-projects`.

For a full or report request, first complete the installed-Skill preflight described in the Report analysis workflow, then start one Report Run before any expensive work. The Report Run freezes Harness, project boundary, one resolved `since`, an exclusive `until`, locale, source inventory, Evidence, and all eligible Lane tickets. Use the bundled `report-run run-all start` command, optionally with `--run-dir <directory>`:

```text
node <skill-directory>/scripts/where-tokens-went.js report-run run-all start --harness codex --cwd <absolute-current-project-path> --since <duration> --locale <locale> --pricing litellm --run-dir <run-directory>
```

```text
node <skill-directory>/scripts/where-tokens-went.js report-run run-all start --harness codex --all-projects --since <duration> --locale <locale> --pricing litellm --run-dir <run-directory>
```

Use `7d` when no period is requested. Global Audit still remains inside the invoking Harness; never substitute another Harness.

The prepare command returns only a compact manifest. It stores the canonical Audit, local first-user-message projection, prompt hashes, source inventory, and timing trace inside the run directory. Never print `audit.json`, pass it as a long argument, or reconstruct it with a temporary Node / PowerShell bridge. Use the host's local file reader for the canonical artifact when the AI needs the complete structured facts. If a host can only accept text, use an explicitly bounded role-specific projection and record omitted fields as unavailable; terminal truncation is never a successful projection.

The direct `inspect` command remains the bundled deterministic tool for usage, window, tools, week, share, and other non-composed views; this bundled inspect command accepts `--cwd <absolute-current-project-path>`, `--since <duration>`, and `--format json`, but it is not the full-report transport protocol.

The local tool is authoritative. Do not recalculate totals, infer missing values as zero, or expose raw history content. With `--pricing litellm`, it makes read-only catalog requests containing only the expected Provider and model identifiers; when some Usage is priced, the report shows an estimated partial amount with priced-Usage coverage and excludes the remainder. Only a selection with no priced Usage leaves currency unavailable while the rest of the audit remains usable.

The JSON result also contains shared cache economics when composition and the selected price source permit it: mutually exclusive Token buckets, cache-read/cache-write rates, composition and price coverage, observed API-equivalent cost, an all-uncached counterfactual, and savings. Currency is always an `estimated` API-equivalent reference, not a subscription bill. The tool requires exact Provider/model identity and every non-zero price dimension; LiteLLM catalog values carry their retrieval source, and unpriced Usage is excluded rather than converted to zero.

It contains `firstRequestBurden`, the earliest valid deduplicated ModelCall per selected Session. Present it as observed first-request burden, with coverage and cache composition; never call it an exact startup tax. It contains Skill evidence only when the local rollout proves a listing, explicit invocation, or verifiable Skill resource/script relation. Preserve `available`, `invoked`, `attributed`, and `unavailable`; a listing does not prove invocation, and causal impact remains unavailable without a counterfactual.

## HTML report visual contract

The local HTML report is generated by the bundled deterministic renderer and must keep the Kami style contract. Do not post-process the report with a second palette or hand-edit packaged runtime files.

For charts, use the approved Kami contrast ladder: #6B6A64 → #504E49 → #2D4E7A → #1B365D. The first two are warm neutrals, #2D4E7A is a chart-only mid-blue, and #1B365D is the focal ink-blue. Add #B8B7B0 or #D4D3CD only when more series are necessary; never introduce saturated multi-hue palettes.

Line charts must combine color with solid/dashed/dotted line types and distinct point symbols. Area fill is reserved for the focal series and stays at or below 0.12 opacity. Legends, tooltips, ARIA descriptions, and equivalent tables remain available; unavailable values stay unavailable.

Choose the local HTML output path only for the final composition after Host Agent analysis and validation. Use `--share <share-path>` for share view. The selected Harness, Current Project versus Global Audit, and privacy boundary must remain unchanged for every view.

The bundled report font is used by default. If the user explicitly supplies a readable local `.ttf`, `.otf`, `.woff`, or `.woff2` file—or names such a file in the request—pass `--font <font-file>` to `report-run compose --json` and optionally `--font-family <name>` for its CSS family name. Do not create another intermediate HTML file or manually post-process the report.

## Report analysis workflow

For a full or report view, the Host Agent completes one atomic ordered workflow bounded by one Report Run. The deterministic Audit is the authority for facts. The report header's first impression and the existing HTML Findings module come from validated Host Agent synthesis rather than fixed threshold prose. The header describes overall activity and usage shape; Findings expose less-obvious patterns; Key Session Analysis explains concrete mechanisms and actions.

The packaged Prompts are the only authorities for Host Agent report prose: read `references/report-synthesis.md` in full before generation for ReportSynthesis (the Audit Overview and report-level Findings, composed as validated `reportSynthesis` or `null`), while reading `references/key-session-analysis.md` in full governs every Key Session Analysis (applying the cross-Session portability test: regenerate an affected invalid entry once). Do not recreate, override, or supplement their generation rules from this Skill or from historical content; the steps below describe only the integration and delivery lifecycle.

Lane output uses `outputContractVersion: 2`. Each Lane Projection carries a frozen Evidence Directory of short handles: `s`/`k`/`f` for selected Sessions, Skills and families, `e` for citable evidence and printable metrics, and `c` for frozen `SKILL.md` fragments. A Worker returns only semantics plus directory selections — `[[eN]]` slots for exact statistics, `e`/`c` handles for support, and object handles for identity. Code restores the canonical identity, facts, units, sources and approved excerpts; a Worker never echoes `runId`, `auditFingerprint`, `snapshotId`, `bundleVersion`, `projectionHash`, `outputContractVersion`, `evidenceRead`, or a measurement, and doing so is rejected. An existing v1 diagnostic caller may still use `report-run ai-accept --output-contract 1`, which keeps the earlier canonical-echo contract; the default entry never infers a contract version from JSON appearance.

0. Before reading history or requesting pricing, run the bundled preflight: `node <skill-directory>/scripts/where-tokens-went.js report-run preflight`. If it fails in a development repository, run `npm run install-local` once and then run the verification again. For an independent installed Skill, preflight verifies the invoking package self-contained; if it fails without a known local distribution source, report that the Skill package must be reinstalled, do not run unrelated npm scripts in the target project, and do not create a Report Run.
1. Call `report-run run-all start` once with the frozen Harness, project selector, period, locale, and pricing. It performs preflight, prepare, `evidence --auto`, Projection creation, and all eligible `ai-start` operations, then returns one compact ticket for each Lane. Retain its `runDir`, `runId`, frozen Scope, `auditFingerprint`, `bundleVersion`, and tickets. A repeated start resumes the same Run and tickets. If start returns `action: advance` with `reason: NO_HISTORY_IN_SCOPE` (no lane tickets), do not dispatch workers; proceed directly to step 3 (`report-run advance`) to produce and deliver the clear no-data report artifact. Read the canonical local artifacts only through the host's file reader; never place the full AuditResult in stdout, a long argument, a prompt wrapper, or a temporary bridge script.
2. Use the Host Capability Bridge only to dispatch native Lane Workers, wait for their terminal results, and execute returned actions.
   - Dispatch all eligible Workers before waiting for any Worker. When native concurrency is available, run Workers in parallel; otherwise run them sequentially with the same tickets and Projections.
   - Each Worker reads only its own `lanes/<lane>/prompt.json` ticket, its own `lanes/<lane>/input.json` Projection, and its own corresponding source Prompt (`prompts/report-synthesis.md`, `prompts/key-session-analysis.md`, or `prompts/skill-insights.md`). It submits only its own raw JSON through `ai-accept`, or a bound ticket failure receipt through `ai-fallback`. It does not read another Lane, widen Scope, rerun preparation or Evidence, compose, render, open HTML, finalize, or cleanup.
   - If the first attempt is rejected, `ai-accept` returns specific validation errors and a `retryTicket`. The current Worker repairs its output and resubmits once within the same Worker session. If the second attempt fails or the Worker cannot continue, the Lane falls back automatically; the Host does not dispatch a replacement Worker.
3. After all Workers return, call `report-run advance --run-dir <run-directory>`. Once all eligible Lanes are terminal, code automatically composes and renders the final HTML, verifies its hash and size outside the lock, and returns `action: "open-html"` with the final HTML path. The Host does not choose retry, fallback, compose, render, finalize, or cleanup from intermediate state.
4. Open only that final HTML path returned by advance, using the Host-native open capability. Then call `report-run advance --run-dir <run-directory> --ui <completed|queued|failed|unavailable>` with the observed UI dispatch outcome. Code verifies HTML integrity and the UI receipt, finalizes delivery, and automatically cleans up sensitive run artifacts, retaining only the final HTML, canonical Audit, manifest, and trace.

For compatibility, the low-level bundled command `compose-report --locale <locale> --html <final-report-path>` remains available for existing callers. It is not the normal full-report protocol and must not receive the full AuditResult through terminal stdout in a new workflow.

For Codex, a non-null Key Session conclusion is accepted when supported by same-Session Evidence. If that task's `keySessionTokenAccounting` status is `reconciled`, strong conclusions are permitted. If that task's status is `mismatch` or `unavailable`, direct interaction and tool behavior Evidence may still support an explanatory mechanism at no more than `moderate` support with a non-empty limitation, but unreconciled Token quantities, shares, or ranks cannot support that mechanism. Claude Code Turn timing and compaction remain capability-dependent; keep missing fields unavailable and do not upgrade observed transcript spans into exact API latency.

## Host Agent diagnosis

The bundled local tool produces authoritative metrics, rankings, coverage, limitations, Evidence, Provenance, and neutral automated checks. It does not diagnose the user’s cause. The Host Agent forms the Finding for the user’s actual question: choose, ignore, or combine checks with rankings, trends, coverage, and limitations; a relevant pattern may be used even when no check fires.

Structure the response as Finding, Evidence, mechanism, action when justified, and material uncertainty without fixed wording. Preserve Scope and every returned value and Provenance. Do not recalculate totals, turn unavailable into zero, infer Provider quota, actual billing, model identity, working time, or causes not supported by Evidence. If the data is proportionate or insufficient, say so rather than manufacture a verdict.

When cache, first-request, or Skill evidence is relevant, carry its Provenance, coverage, exact pricing limitation, and evidence boundary into the Finding. Keep direct Skill resource footprint, observed association, and causal impact separate; do not infer a cause from a Skill listing.

For a report request, delivery is complete only after the same conversation turn produces and opens the final local HTML containing a validated Audit Overview and report-level Findings, then gives the strongest supported Finding with Evidence, mechanism, action when justified, and uncertainty in conversation. Do not end after Audit JSON, an internal CLI result, a preliminary fallback HTML, a report path, or merely opening the HTML; do not return a diagnosis without the requested report. The local full HTML includes each displayed Turn's complete first user message for recognition; sanitized share, JSON, and text remove it. Never include model responses, source code, command arguments, shell output, tool results, credentials, or base64 payloads in any report projection.
